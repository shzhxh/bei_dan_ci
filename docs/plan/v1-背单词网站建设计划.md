# 背单词网站建设计划

**项目代号：三千里（3K Words）**　|　版本 v1.0　|　2026-11-19　|　状态：待评审

> 一句话：把柯林斯 5★/4★/3★ 共 3,300 个高频词，编成 450 篇 150–265 词的短文，用「读—讲—背—测—复习」的闭环，做成一个纯网页、移动优先、可离线使用的学习站。

---

## 0. 摘要

### 0.1 四个关键数字

| 数字 | 含义 | 依据 |
|---|---|---|
| **3,300** | 5★ 680 + 4★ 1,040 + 3★ 1,580 | 柯林斯 COBUILD 五星词频分层（公开口径，需实测复核） |
| **450 篇** | 主套 300 篇 + 中考套 150 篇 | 3,300 / 11 与 1,650 / 11，每篇 11 个新词 |
| **100%** | 词表覆盖率硬门禁 | 每个词必须有且仅有一个「首现篇」，脚本可验 |
| **≥5 次** | 核心词接触下限 | 正文化 3 次 + 复习模块 ≥2 次（间隔重复） |

### 0.2 三条差异化

1. **不是词卡站，是「背短文」**：背诵做成四阶脚手架（全文 → 挖空 → 首字母 → 回译），而不是只让用户读一遍。
2. **不是泛读站，是「受控写作」**：每篇生词密度 ≤6%（中考套 ≤7.5%），超纲词 ≤2 个且必须带注，保证「一篇读完不崩溃」。
3. **不是黑盒课，是「可核算」**：词表覆盖率、复现达标率、篇目生词密度全部可视化，每次构建自动校验，缺一个词就构建失败。

### 0.3 本计划的三个判断

- **内容量是真正的成本中心，不是技术。** 450 篇 ≈ 8.8 万英文词，必须用「词表驱动 + AI 初稿 + 人工双审 + 脚本门禁」的流水线，否则产能和一致性都撑不住。
- **中考套先行。** 1,650 词位、150 篇、句式简单，是验证「背短文是否真的更轻松」的最低成本样本；验证通过再铺主套。
- **首期不做账号。** 进度存本地，可导出导入；账号只服务于跨端同步，放到第二阶段。降低启动门槛，也避开未成年人数据合规的复杂度。

## 1. 产品定义与依据

### 1.1 核心命题与可验证假设

产品的底层信念是「在语境中反复遇到同一个词，比对着词表重复记忆更有效」。为了让这句话可被验证而不是口号，拆成三个假设：

| 编号 | 假设 | 验证方式 | 通过线 |
|---|---|---|---|
| H1 | 短文组 7 日词汇保持率高于词卡组 | P1 内测分组对照（各 30 人） | 高 ≥10 个百分点 |
| H2 | 生词密度 ≤7% 时首篇完成率显著提升 | 同一批用户在 5%/9% 两种版本上的完成率 | 首篇完成率 ≥70% |
| H3 | 完成四阶背诵者产出能力更强 | 完成组 vs 仅阅读组的中译英小测 | 正确率 ≥80% |

三条假设对应三次实验，结论回写进内容规范；不通过就改规范，而不是改宣传语。

### 1.2 用户与场景

| 人群 | 规模判断 | 核心诉求 | 对应课程 | 关键约束 |
|---|---|---|---|---|
| 初中生（中考） | 主力 | 考纲词必须全会，不能超纲 | 中考套 J1500 | 注意力短、需要即时反馈 |
| 高中生（高考） | 主力 | 阅读提分，词汇量 3,500 | 主套 + 高考补漏包 | 时间碎片化 |
| 大学生（四六级） | 次主力 | 快速过一遍高频词 | 主套 + CET 扩展包 | 自律性较好、接受长文 |
| 基础较弱成年人 | 次主力 | 从零重学，怕挫败 | 中考套 J1500 | 需要低门槛与鼓励 |

**使用场景**：通勤 10–15 分钟（手机，读 1 篇 + 做 8 题）、课间 5 分钟（复习队列）、睡前 20 分钟（精读 + 背诵）、考前冲刺（按考纲筛选 + 错题重刷）。

**设备假设**：移动端 80%+；桌面端主要用于长文精读、打印背诵稿。

### 1.3 教学法依据 → 产品要求

| 依据 | 结论 | 产品落点 |
|---|---|---|
| 高频词覆盖律 | 约 3,000 词可覆盖日常文本 92–95% 的 token（需实测） | 词表以频次为骨架，不按字母序 |
| 编码特异性 / 语境记忆 | 词在有意义语篇中首现，记忆线索更多 | 每个词有唯一「首现篇」 |
| 提取练习（retrieval practice） | 回忆比重读有效 | 读后立刻测；背诵靠遮词回忆 |
| 间隔重复 | 1/3/7/16/35 天的间隔最经济 | SRS 复习队列 |
| 受控词汇阅读（graded reading） | 已知词占比高才读得下去 | 生词密度硬上限 + 超纲词配额 |
| 词块理论 | 搭配比孤立释义更可迁移 | 每篇标注 3–5 个搭配 |
| 认知负荷理论 | 一次只增加一个难度维度 | 每篇 1 个语法点、3–5 段 |

**关于「95%」的口径说明（重要）**：95% 指的是**文本 token 覆盖率**（running words 中被认识的比例），不是词表 type 覆盖率。词表覆盖 3,300 个词 ≠ 覆盖任何文本 95% 的词。产品里两个指标分开算、分开展示，避免自欺。

### 1.4 产品原则

1. **内容优先**：一屏读完一篇；任何动效不得打断阅读。
2. **默认不翻译**：译文默认折叠。看得懂中文不等于学会了英文。
3. **无账号可用**：打开即学，进度本地保存，可导出 JSON。
4. **可验证**：所有内容指标由脚本复核，人说了不算。
5. **不承诺速成**：明示「每天 15 分钟，约 30 周走完主套」这类可核对的口径（按每日 1 篇估算，随进度自适应）。
6. **不碰柯林斯商标**：站名、文案、SEO 均不使用 Collins/柯林斯作为品牌名，只在方法论页做事实性说明。

### 1.5 范围与非目标

**首年做**：两套课程、阅读器、四阶背诵、即时检测、SRS 复习、进度与覆盖看板、词库与词条页、内容生产脚本与质检后台。

**首年不做**：口语评分、AI 外教对话、直播课、社区/UGC、多语种、教师端、排行榜。这些都会稀释内容产能，等 450 篇跑通再议。

## 2. 词汇体系：分层、选题与覆盖率

### 2.1 词表基座（单一事实源）

全站只有一个词表文件 `lexicon.json`（或 SQLite 导出），页面、脚本、后台全部只读它。任何词表改动走 diff 评审并升版本号（`lexicon@2026.11.19`）。

**数据源策略**：

| 用途 | 来源 | 说明 |
|---|---|---|
| 星级、考纲标签、词频 | ECDICT | 含 `collins`、`tag`（zk/gk/cet4/cet6）、`bnc`、`frq` 字段，可一次拿到骨架 |
| 考纲权威口径 | 义务教育课标词表、高考考试说明词表 | 用于校验与补漏，不用来当唯一来源 |
| 释义校对 | Wiktionary、CC-CEDICT | 只做交叉核对 |
| 中文释义、例句、短文 | **全部自建** | 规避词典版权；不复刻柯林斯释义与例句 |

**P0 必须完成的许可证核验**：ECDICT 及其上游数据的商用与再分发许可、TTS 服务商用授权、字体授权。核验不通过的字段一律替换，不带病上线。

**词表字段**（详见附录 A）：

```yaml
lemma: abandon
pos: [v]
stars: 4                 # 柯林斯星级 1-5
freq: { bnc: 2103, coca: 1890 }
exams: [gk, cet4, cet6]  # zk 中考 / gk 高考 / cet4 / cet6
cefr: B2
senses:
  - id: 1
    zh: 放弃；抛弃
    pattern: "abandon sth/sb"
collocations: [abandon a plan, abandon ship]
forms: [abandons, abandoned, abandoning]
sets: [s3000, j1500]
assign: { first: s3000-l3-u04-02, recycle: [s3000-l3-u05-01] }
status: published
```

### 2.2 两套课程

| 课程 | 定位 | 词位 | 篇数 | 结构 | 篇长（词） | 新词/篇 | 生词密度上限 |
|---|---|---:|---:|---|---:|---:|---:|
| **主套 S3000** | 系统通关 3,300 高频词，面向高中/四六级/成人 | 3,300 | 300 | 6 级 × 10 单元 × 5 篇 | 185–265 | 11 | 6% |
| **中考套 J1500** | 低门槛入口，面向初中/弱基础成人 | 1,650 | 150 | 5 级 × 6 单元 × 5 篇 | 150–180 | 11 | 7.5% |

**J 套为什么是 1,650 而不是 1,500**：5★+4★ 合计 1,720，是中考的天然骨架；再与考纲做差集，补入约 100–150 个「星级不高但考纲必考」的词，最终入库 1,650。对外宣传用「1,500 核心词」，实际保证考纲 100% 覆盖。**宁可多 150，不可漏一个考纲词。**

**两套的关系**：J ⊂ S（约 95% 重合）。J 的短文更短、句式更简单、主题更生活化；S 同词不同文，语境不同，天然多一次复现。完成 J 套后经诊断测可免修 S 的 L1–L3。

**容量自检**：

- S：5 篇 × 11 词 = 55 词/单元；10 单元 = 550 词/级；6 级 = 3,300 词，与词表 1:1，零冗余。
- J：5 篇 × 11 词 = 55 词/单元；6 单元 = 330 词/级；5 级 = 1,650 词。
- 正文总量：300 × 215 + 150 × 160 ≈ 88,500 词（约 8.8 万）。

### 2.3 星级 × 考纲 × 考试：三层映射

星级回答「这个词多常用」，考纲回答「这个词是否必须考」。两者不等价，必须做交集与差集。

| 目标集 | 规模（约） | 3,300 高频词可覆盖 | 差集处理 |
|---|---:|---|---|
| 中考 | 1,500–1,700 | 90–95% | J 套补漏 ≤150 词 |
| 高考 | 3,500 | 85–90% | 「高考补漏包」300–500 词，P4 上线 |
| CET4 | 4,500 | 75–80% | 扩展包，P4 |
| CET6 | 6,000 | 60–65% | 扩展包，P5（可选） |

> 上表为**预估**。P0 用真实词表跑一遍交集，把数字回填成实测值，并把「星级覆盖不到的考纲词」导出成补漏清单。这张表是整个选题的输入。

**选词优先级规则**（同一篇内排序）：

1. 考纲必考 > 星级高 > 词频高；
2. 实词优先（名词/动词/形容词/副词），功能词只作已学词，不作目标词；
3. 同一篇内词性配比大致 4 名 + 4 动 + 3 形/副，避免一篇全是抽象名词；
4. 同族词（abandon / abandoned / abandonment）不同篇，避免「假复现」。

### 2.4 覆盖率核算模型

设词表为 T，已发布篇目集合为 P，篇目 p 的目标词集合为 W_p。

| 指标 | 公式 | 门槛 | 用途 |
|---|---|---|---|
| 内容覆盖率（type） | `C = \|{w ∈ T : ∃p, w ∈ W_p}\| / \|T\|` | **100%** | 发布硬门禁 |
| 出现次数 | `occ(w) = \|{p : w ∈ W_p}\|` | 5★ ≥3，4★/3★ ≥2 | 复现达标 |
| 复现达标率 | `R = \|{w : occ(w) ≥ n(w)}\| / \|T\|` | ≥95% | 质量看板 |
| 生词密度 | `d_p = \|W_p\| / words(p)` | S ≤6%，J ≤7.5% | 单篇门禁 |
| 文本覆盖率（token） | `TC = Σ_{w ∈ L} count_C(w) / \|C\|` | 学完 S 套 92–95% | 对外口径 |
| 考纲覆盖率 | `E_c = \|F ∩ E\| / \|E\|` | 中考 100%，高考 ≥90% | 分考试看板 |

其中 L 为学习者已学词集合，C 为 100 万词抽样语料（新闻/小说/口语按 4:4:2 配比）。

**工作示例（主套）**：

- 3,300 词，300 篇，11 新词/篇 → 3,300 个首现位，正好一一对应。
- 复现需求：680×3 + 1,040×2 + 1,580×2 = **7,280 次** → 每篇 24.3 次（11 新 + 13.3 复现）。
- 平均篇长 215 词 → 生词密度 5.1%，目标词密度 11.3%。前者是难度指标，后者是复现指标，分开看。

**看板**：按「课程 / 级别 / 单元」三级展示覆盖率、复现达标率、密度分布、缺陷数；红色 = 有缺口，黄色 = 达标但接近阈值，绿色 = 安全。缺口一键导出为下一批选题清单。

**语法递进**（每篇只设 1 个主语法点）：

| 级别 | 主语法点范围 |
|---|---|

### 2.6 多义词与词形规则

| 问题 | 规则 |
|---|---|
| 计量单位 | 以 lemma 计；派生词若在词表内则单独占位 |
| 多义词 | 高频词取 1 个核心义项 + 常见搭配；前 500 高频词可拆成 2 张卡（不同篇） |
| 一词多性 | 以最高频词性为首现词性，其余词性在精讲里补一句 |
| 同族词 | 禁止同篇出现，防止「看起来复现了其实没有」 |
| 短语动词 | 作为独立词条（give up / look after），与单词同池管理 |
| 专有名词 | 不计入目标词，不计入生词密度，需给注 |

## 3. 短文体系：编排、复现与难度控制

### 3.1 篇目规格

| 级别 | 篇长（词） | 平均句长 | 段数 | Flesch 阅读难度 | 新词 | 复现位 | 目标词密度 |
|---|---:|---:|---:|---|---:|---:|---:|
| J L1 | 150–165 | ≤11 | 3 | 85–92 | 11 | 11 | ≤15% |
| J L2–L3 | 155–170 | ≤12 | 3 | 80–88 | 11 | 11 | ≤15% |
| J L4–L5 | 165–180 | ≤13 | 3–4 | 75–85 | 11 | 11 | ≤15% |
| S L1 | 185–200 | ≤13 | 3–4 | 70–80 | 11 | 13–14 | ≤14% |
| S L2 | 190–210 | ≤15 | 4 | 65–75 | 11 | 13–14 | ≤14% |
| S L3 | 200–225 | ≤16 | 4 | 60–70 | 11 | 13–14 | ≤13% |
| S L4 | 210–235 | ≤18 | 4–5 | 58–68 | 11 | 13–14 | ≤13% |
| S L5 | 225–245 | ≤19 | 5 | 55–65 | 11 | 13–14 | ≤13% |
| S L6 | 235–265 | ≤20 | 5 | 52–62 | 11 | 13–14 | ≤13% |

> 「目标词密度」含复现词，只用于控制文本负荷；真正的难度红线是「生词密度」（S ≤6%，J ≤7.5%）。复现词是已学词，不算生词。

### 3.2 单篇结构模板

**frontmatter（机器可校验）**

```yaml
id: s3000-l3-u04-02
set: s3000            # s3000 | j1500
level: 3
unit: 4
order: 2
title: The Late Train
topic: 出行与城市
genre: narrative
grammar: 过去完成时
targets:              # 11 个，带义项 id
  - { lemma: crowded, sense: 1 }
  - { lemma: delay, sense: 1 }
  - { lemma: annoy, sense: 1 }
recycle: [rush, platform, apologize, ...]   # 13 个已学词
glosses: [{ word: signal failure, zh: 信号故障 }]  # ≤2 个超纲词
metrics: { words: 214, new_density: 0.051, readability: 62, avg_sentence: 15.2 }
audio: /audio/s3000-l3-u04-02.mp3
status: reviewed      # draft | reviewed | published
version: 3
```

**正文结构**（固定五段式，降低阅读预期成本）：

1. **一句导读**（中文，≤25 字）：告诉用户这篇大概讲什么，不剧透结局。
2. **正文**：3–5 段，每段 2–4 句，目标词加粗但不高亮释义。
3. **词表区**：11 个目标词 + 音标 + 中文释义 + 原句摘录 + 搭配。
4. **检测区**：8 题（见 4.3）。
5. **背诵区**：四阶脚手架入口（见 4.2）。

### 3.3 受控词汇写作规则（硬规则，脚本可查）

| 编号 | 规则 | 校验方式 |
|---|---|---|
| R1 | 正文用词 ∈ {本篇 11 个目标词} ∪ {已学词} ∪ {功能词白名单} | 脚本比对词表 |
| R2 | 超纲词 ≤2 个，且必须有中文注 | 脚本 + 人工 |
| R3 | 每个目标词在篇内出现 ≥2 次（首现 + 至少 1 次自然复现） | 词频统计 |
| R4 | 标注 3–5 个搭配（collocation），不标注孤立词义 | 人工 |
| R5 | 每篇 1 个主语法点，不引入未教语法（≤1 处例外，需注） | 人工审 |
| R6 | 同族词不共篇 | 脚本 |
| R7 | 事实、文化、政治、宗教中性；不出现真实品牌与真实人物负面描述 | 人工审 |
| R8 | 可朗读性：不连续堆叠 3 个以上多音节生词 | TTS 试听 + 人工 |

### 3.4 复现策略

复现分三层，缺一层都会导致「学过就忘」。

| 层级 | 机制 | 数量 | 说明 |
|---|---|---|---|
| 篇内复现 | 首现词在本篇再出现 1 次 | 每词 ≥1 | 写作时强制 |
| 篇间复现 | 首现后 1–2 个单元内，进入后续篇目的 `recycle` 配额 | S 每篇 13 位 / J 每篇 11 位 | 从「到期复现队列」按优先级取词 |
| 复习复现 | SRS 卡片，间隔 1/3/7/16/35 天 | 每词 ≥2 次 | 卡片例句取自首现篇，保持语境一致 |

**复现配额的取词优先级**：① 已到复现窗口且欠次数的词 → ② 与本篇主题同语义场的词 → ③ 5★ 核心词。避免「为了复现硬塞」，塞不进就留给下篇，队列会自动顺延。

**复现形式优先级**：原搭配复现 > 同义替换 > 新搭配。原搭配复现最省认知成本，新搭配最能迁移，按 6:4 配比。

### 3.5 难度与长度控制

**五条红线**（任一不过，篇目不得发布）：

1. 生词密度：S ≤6%，J ≤7.5%。
2. 超纲词 ≤2 个且全部有注。
3. 平均句长、最长句长不超该级上限（最长句 ≤ 平均句长 × 1.8）。
4. Flesch Reading Ease 落在该级区间内。
5. 目标词篇内出现次数全部 ≥2。

**两条软指标**（进入评审，不阻断）：TTS 试听流畅度、朗读时长（J 套 60–80 秒，S 套 80–120 秒）。

### 3.6 保证 3,300 词「全覆盖、不遗漏」的三道闸

只靠人盯着表格，一定会漏。必须机器兜底。

**第一道：分配账簿（唯一事实源）**

`assignment.tsv` 每词一行，记录 `lemma / set / level / unit / first_passage / recycle_passages / occ / status`。任何篇目增删改，先改账簿，再改正文。账簿与词表做双向 diff：账簿里没有的词 = 未分配；账簿里有但词表没有的词 = 脏数据。

**第二道：构建门禁（硬失败）**

每次构建跑 `audit-content`：缺词、少次数、超密度、超纲词无注、frontmatter 不合 schema、篇目重复（simhash），任一命中即构建失败，不允许「先上线后补」。

**第三道：覆盖率看板 + 版本冻结**

看板按级别展示覆盖率曲线；未覆盖词可一键导出为「下一批选题包」。每批内容上线前冻结词表版本，避免「写着写着词表变了」。

### 3.7 示例片段（仅示意写作标准，非正式稿件）

目标词：`crowded, delay, annoy, adjust, avoid, platform`（节选，实际 11 个）

> The train was so **crowded** that I could hardly find a seat. A signal failure had **delayed** it by twenty minutes, which **annoyed** everyone on the **platform**. Instead of complaining, I **adjusted** my plan: I got off at the next stop and walked the rest of the way to **avoid** being late again.

这段 60 词里 6 个目标词各出现 1 次（正式稿需每词 ≥2 次），生词密度 10%（正式稿需压到 6% 以下），超纲词 `signal failure` 需加注。示例用来对齐「什么算合格」，不作为成稿。

## 4. 学习者路径与页面结构

### 4.1 学习闭环

```
首次进入
  └─ 首页（选课程 / 30 秒说明 / 试读一篇）
       └─ 诊断测（10 题自适应，估词汇量，推荐起点）
            └─ 级别地图（单元卡片 + 进度）
                 └─ 单元页（5 篇 + 单元测）
                      └─ 短文页【阅读 → 精讲 → 背诵 → 检测】
                           └─ 复习队列（次日 / 3 日 / 7 日 / 16 日 / 35 日）
                                └─ 进度页（覆盖率、连续天数、错词）
```

一个单元 = 5 篇 ≈ 5 天；每天 15 分钟 = 1 篇新学 + 10 分钟复习。主套 300 篇按每日 1 篇计约 30 周，产品内按实际进度动态提示，不做倒计时压迫。

### 4.2 背诵四阶脚手架（核心差异功能）

| 阶段 | 呈现方式 | 用户任务 | 通过标准 |
|---|---|---|---|
| B1 全文跟读 | 全文 + 音频逐句高亮 | 跟读 2 遍，标记不熟的句子 | 完成即可 |
| B2 目标词挖空 | 11 个目标词挖空，给首字母 | 填空 | ≥9/11 |
| B3 关键句首字母 | 每段首句给首字母提示 | 口头/键盘补全 | ≥4/5 段 |
| B4 回译 | 只给中文译文 | 说出/键入英文 | ≥70% 句意命中 |

四阶可跳级，但 B2 未过时不建议进 B3（页面提示，不强制）。B4 用「关键词命中 + 语序相似度」做宽松判定，不要求逐字一致。

### 4.3 检测题型

| 题型 | 考察 | 题量 | 判分 |
|---|---|---:|---|
| 词义匹配 | 再认 | 3 | 自动 |
| 句中填空 | 语境运用 | 2 | 自动（严格匹配 + 变形容错） |
| 搭配选择 | 词块 | 1 | 自动 |
| 听音选词 | 音形连接 | 1 | 自动（TTS） |
| 句意理解 | 阅读理解 | 1 | 自动（三选一） |

8 题全自动判分，错题自动进错题本并生成 SRS 卡片。单元末 20 题综合测，级别末 40 题阶段测（含前测同源题，用于算保持率）。

### 4.4 信息架构

```
/                         首页
├─ /start                 诊断测
├─ /learn                  课程选择
│   ├─ /learn/s3000        主套地图（6 级）
│   │   └─ /learn/s3000/l3         级别页（10 单元）
│   │       └─ /learn/s3000/l3/u04 单元页（5 篇）
```

### 4.5 页面清单

| 页面 | 目的 | 核心组件 | 首期 |
|---|---|---|---|
| 首页 | 30 秒说清「是什么、怎么用、效果如何」 | 价值主张、两套入口、试读篇、方法论摘要 | ✅ |

| 级别地图 | 看见全貌与进度 | 单元卡片、完成度、锁定态 | ✅ |

| 方法论页 | 解释依据与边界 | 95% 口径、复现机制、版权说明 | ✅ |
| 管理后台 | 内容生产与质检 | 覆盖率看板、缺陷列表、发布开关 | P1（内部） |

### 4.6 关键页面说明

**短文页**是全部价值所在，四态切换不换页：

- **阅读态**：正文 + 音频；点任意词弹出词卡（音标、释义、搭配、加入生词本）；译文默认折叠；字号/行距/护眼模式可调。
- **精讲态**：逐段展开目标词讲解与搭配，不打断正文位置（侧栏/下抽屉）。
- **背诵态**：四阶脚手架，进入即计时（可选），退出保存进度。
- **检测态**：8 题逐题作答，即时反馈，错题高亮原句。

**移动优先**：单列布局，底部固定「上一段/下一段/播放」，拇指可达区放主按钮；桌面端双栏（正文 + 词卡侧栏）。

### 4.7 进度与激励

- **覆盖率环**：已学词 / 当前课程总词，附「对日常文本的 token 覆盖」估算。
- **连续学习天数**：只记录，不做惩罚性断签文案。
- **单元徽章**：完成单元 + 单元测 ≥80% 才点亮，避免「点开即完成」。
- **首期不做排行榜**：外部动机容易替代内在动机，等留存稳定再评估。

## 5. 内容生产流程与质量控制

### 5.1 角色

| 角色 | 职责 | 配置建议 |
|---|---|---|
| 内容主编 | 定规范、终审、词表版本冻结 | 1 人 |
| 英语教研 | 选题、改写、语法与文化审校 | 2 人 |
| 母语审校 | 语言地道性抽检（P2 起） | 兼职 1 人 |
| 词表/数据工程 | 词表校准、分配算法、审计脚本 | 1 人（可与前端复用人） |
| 前端/全栈 | 站点、阅读器、SRS、后台 | 1–2 人 |
| 设计 | 设计系统、关键页面 | 兼职 |
| 运营 | 内容日历、用户反馈、数据复盘 | P2 起 1 人 |

### 5.2 七步流水线

| 步骤 | 输入 | 输出 | 责任 | 出口标准 |
|---|---|---|---|---|
| 1 选题排产 | 主题矩阵 + 未覆盖词清单 | 选题单（主题/级别/语法点） | 主编 | 与矩阵配额一致 |
| 2 生成约束包 | 词表 + 账簿 | `brief.json`（目标词/可用词集/语法点/主题/长度） | 数据工程 | 脚本校验通过 |
| 3 初稿 | 约束包 | 3 个候选稿 | 撰稿（AI 辅助） | 词命中 ≥8/11 |
| 4 自动质检 | 候选稿 | 指标报告 + 淘汰建议 | 脚本 | 五项红线全过 |
| 5 人工改写 | 最优候选 | 成稿 + 词表区 + 8 题 | 教研 | 逐词核对，搭配自然 |
| 6 双人审校 | 成稿 | 审校记录 + 修订稿 | 教研 A/B | 零阻断项，建议项已处理 |
| 7 入库发布 | 修订稿 + 音频 | 上线篇目 + 看板更新 | 主编 | 构建门禁通过 |

**为什么先让 AI 出 3 稿**：约束包已经把「必须出现哪些词、只能用哪些词、多长」全部锁死，模型的任务退化成「在笼子里讲故事」，命中率和可用性远高于开放式创作。人工只做「选 + 改 + 审」。

### 5.4 质检清单

| 检查项 | 方法 | 阈值 | 阻断 |
|---|---|---|---|
| 词表命中 | 脚本比对 targets | 11/11 | ✅ |
| 篇内复现 | 词频统计 | 每词 ≥2 | ✅ |
| 生词密度 | 脚本计算 | S ≤6%，J ≤7.5% | ✅ |
| 超纲词 | 比对可用词集 | ≤2 且有注 | ✅ |
| 句长/可读性 | 脚本 + Flesch | 在级别区间 | ✅ |
| 语法点 | 人工审 | 1 个主点，无未教语法 | ✅ |
| 搭配自然度 | 人工 + 母语抽检 | 无中式搭配 | ✅ |
| 事实/文化/敏感 | 人工审 | 中性、准确 | ✅ |
| 拼写/标点/时态一致 | 工具 + 人工 | 0 错 | ✅ |
| 篇目重复 | simhash | 相似度 <0.8 | ✅ |
| 音频对齐 | 自动切分 + 抽听 | 句级对齐 | ⬜ |
| 中文译文准确 | 人工 | 意译准确、不增删 | ⬜ |

**审校比例**：前 50 篇 100% 双人审 + 母语抽检 20%；流程稳定后双人审 100%、母语抽检 10%。语言缺陷率目标 <1 处/千词。

### 5.5 版本与缺陷管理

- 每篇有 `id + version + changelog`，正文、译文、题目、音频同版本号。
- 缺陷单字段：篇目、位置、类型（语言/事实/教学/技术）、严重度、修复版本。
- 已发布篇目改动必须走「修订 → 复审 → 重新构建」，不允许后台直接改线上文本。
- 每月抽样重审 5%，重点看「用户错得最多的篇目」——错题率高不一定是用户问题，可能是题目或讲解有问题。

### 5.6 产能与排期输入（假设值，非承诺）

单篇综合工时约 3.0 人时：AI 初稿 0.3 + 人工改写 1.0 + 双审 0.8 + 题目与音频 0.5 + 入库 0.4。450 篇约 1,350 人时。

结论：**不要一次铺 450 篇**。先做 30 篇验证闭环与单位成本，再按「每批 50 篇」滚动排产；每批结束复盘一次单位成本与缺陷率。

## 6. 技术实现

### 6.1 架构选型

**推荐：Astro + TypeScript + Tailwind + 内容集合（Content Collections）+ 岛屿组件（Preact/React）+ 纯静态部署。**

| 选项 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Astro 静态站** | 默认零 JS、SEO 友好、构建快、成本低、可离线 | 交互要岛屿化 | **首选** |
| Next.js SSG | 生态大、团队熟悉 | 首屏 JS 偏重、配置复杂 | 备选 |
| 纯 SPA（Vite+React） | 交互顺 | SEO 差、首屏慢 | 不选 |

**为什么静态优先**：内容型产品，页面量约 450 篇 + 3,300 词条 ≈ 3,750 个可索引页面，静态化后 SEO 与访问速度都是最优；学习进度存 `localStorage` 即可支撑「打开即学」；后续加账号只加一个同步接口，不动内容层。

**分层**：

```
内容层   Markdown/MDX + JSON（lexicon、assignment、reports）
构建层   Astro 构建 + audit 脚本 + 音频生成
交互层   阅读器 / 背诵 / 检测 / SRS（岛屿组件，共享一个 progress store）
存储层   localStorage（v1）→ Supabase（v2，可选）
部署层   Cloudflare Pages / Vercel（海外）+ 国内镜像（视备案情况）
```

### 6.2 数据模型

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `Lexicon` | lemma, pos, stars, exams, senses[], collocations[], forms[] | 词表，只读 |
| `Passage` | id, set, level, unit, order, targets[], recycle[], metrics, status | 篇目 |
| `Unit` | id, level, passage_ids[], test_id | 单元 |
| `Level` | id, set, unit_ids[], stage_test_id | 级别 |
| `Question` | id, passage_id, type, stem, options, answer, explanation | 题目 |
| `Progress` | learned[], srs_cards[], wrong[], streak, last_active | 用户进度（本地/云端同构） |
| `Assignment` | lemma, first_passage, recycle_passages[], occ, status | 分配账簿 |

`Progress` 用版本化 schema（`schema_version`），升级时写迁移函数，避免用户进度丢失。

### 6.3 关键模块

1. **阅读器**：分段渲染、点词查义（词形还原到 lemma）、译文折叠、TTS 播放与句级高亮、字号/主题设置。
2. **背诵引擎**：四阶状态机 + 挖空生成 + 首字母提示 + 回译的宽松判定（关键词覆盖 + 语序相似度）。
3. **SRS**：简化 SM-2（again/hard/good/easy 四档），间隔 1/3/7/16/35，卡片绑定首现篇例句。
4. **进度与统计**：覆盖率计算、连续天数、错词分布、导出/导入 JSON。
5. **音频**：构建期批量生成 MP3（Edge-TTS/Azure），按句切分存时间戳；运行时失败回退 Web Speech API。
6. **搜索**：Pagefind 静态索引，支持词形与中文释义检索。
7. **后台**：覆盖率看板、缺陷列表、发布开关（读取 `reports/*.json`，只读展示 + 触发重建）。

### 6.4 构建期质量门禁

```js
// scripts/audit-content.mjs（示意）
const lex = loadLexicon();
const passages = loadPublishedPassages();
const covered = new Map();
for (const p of passages) {
  for (const t of p.targets) covered.set(t.lemma, (covered.get(t.lemma) || 0) + 1);
  assert(p.targets.length === 11, `${p.id} 目标词数不为 11`);
  assert(p.metrics.new_density <= threshold(p.set), `${p.id} 生词密度超标`);
  assert(p.glosses.length <= 2, `${p.id} 超纲词超过 2 个`);
}
const missing = lex.filter(w => w.sets.includes(SET) && !covered.has(w.lemma));
if (missing.length) fail(`未覆盖 ${missing.length} 词`, missing);
const lowFreq = [...covered].filter(([lemma, n]) => n < requiredTimes(lemma));
if (lowFreq.length) warn(`复现不足 ${lowFreq.length} 词`);
```

门禁输出 `reports/coverage.json`、`reports/defects.json`，同时供后台看板与 CI 使用。**缺词 = 构建失败**，不接受「先发后补」。

### 6.5 性能、SEO、无障碍与国内访问

| 维度 | 目标 | 做法 |
|---|---|---|
| 性能 | LCP <2.5s，首屏 JS <100KB | 静态输出、岛屿懒加载、字体子集、图片 AVIF |
| SEO | 3,750 页可索引 | 每篇/每词独立 URL、结构化数据（LearningResource）、sitemap、语义化标题 |
| 无障碍 | WCAG 2.1 AA | 键盘可达、对比度 ≥4.5:1、字号可调、朗读支持、减少动效开关 |
| 离线 | 已学篇目可离线复习 | PWA + Service Worker 缓存阅读与复习资源 |
| 国内访问 | 首屏稳定 | 若主用户在国内：域名备案 + 国内 CDN/对象存储；否则海外托管 + 国内可访问性实测，不达标再加镜像 |

**这是一项需要拍板的决策**：备案需要主体资质与周期，建议 P0 就定，别等上线前才处理。

### 6.6 隐私与合规

- 默认不采集个人信息；进度本地存储。
- 若上账号：仅邮箱/第三方登录标识，最小化采集；提供导出与删除。
- 未成年人：默认开启「家长模式」（隐藏社交、限制单次时长提示），不投放个性化广告。
- 版权：星级数据仅作内部选题参考；释义、例句、短文、译文、题目均为原创或已获授权；页面附版权与数据来源说明。

## 7. 分期迭代

### 7.1 原则

- **每期交付一个闭环**，不是「半个功能 + 半个内容」。
- **内容与功能并行**：功能做阅读器时，内容在写第一批 30 篇。
- **规模由验证结果决定**，不由计划书决定。每期结束设 go/no-go。

### 7.2 阶段表

| 阶段 | 名称 | 范围 | 主要交付 | 出口标准 |
|---|---|---|---|---|
| **P0** | 基座与试点 | 词表、规范、5 篇样稿、审计脚本、设计系统骨架 | `lexicon.json`、`assignment.tsv`、内容规范 v1、5 篇过审样稿、`audit-content` 跑通、覆盖率初版报表 | 词表口径实测回填；5 篇五项红线全过；单位成本有数 |
| **P1** | 闭环 MVP | 中考套 L1（30 篇）+ 阅读器/背诵/检测/SRS/进度 + 部署 | 可用的完整学习闭环；20 人内测 | 首篇完成率 ≥70%；7 日留存 ≥25%；H2 有初步结论 |
| **P2** | 规模复制 | 中考套全量 150 篇 + 主套 L1–L2 100 篇；账号与跨端同步；搜索与词条页 | 250 篇上线；覆盖率看板；SEO 开始收录 | 中考套覆盖率 100%；已发布批次审计全绿；复现达标 ≥95%；缺陷率 <1/千词 |
| **P3** | 中段与体验深化 | 主套 L3–L4 100 篇；全量音频；错题本；阶段测；PWA 离线 | 350 篇；音频全覆盖；阶段测可算保持率 | 单元完成率 ≥35%；30 日保持率 ≥65% |
| **P4** | 收尾与扩展 | 主套 L5–L6 100 篇；高考/CET4 补漏包；数据驱动重写 | 450 篇全量；3,300 词 token 覆盖实测 | 3,300 词 100% 上线；搜索流量占比达标 |
| **P5** | 生态（可选） | 班级/教师端、打卡活动、开放 API | 按数据决定 | 只有 P4 指标达标才启动 |

### 7.3 两个关键决策点

**Gate 1（P0 结束）——这个生意能不能做？**

- 词表实测是否与 3,300 口径一致？考纲差集有多大？
- 单篇综合成本能否压到可接受区间？
- 5 篇样稿的教研与内测评价是否 ≥4.2/5？

任一为否：缩范围（例如只做中考套 150 篇），而不是硬推 450 篇。

**Gate 2（P1 结束）——这个方法有没有效？**

- 首篇完成率 ≥70%、7 日留存 ≥25%、H1/H2 方向正确。
- 背诵四阶的完成率是否 ≥30%（低于此说明脚手架太重，需要简化）。

不达标：先改教学环节，不扩内容量。内容是最贵的资产，方向错了扩得越多亏得越多。

## 8. 成功标准与度量

### 8.1 指标树

```
北极星：每周完成短文数（WCP）
├─ 内容供给
│   ├─ 词表覆盖率（硬 100%）
│   ├─ 复现达标率（≥95%）
│   ├─ 生词密度合规率（100%）
│   └─ 语言缺陷率（<1/千词）
├─ 学习行为
│   ├─ 首篇完成率（≥70%）
│   ├─ 单元完成率（≥35%）
│   ├─ 背诵四阶完成率（≥30%）
│   └─ 复习队列完成率（≥60%）
├─ 学习效果
│   ├─ 即时测正确率（≥85%）
│   ├─ 7 日保持率（≥75%）
│   ├─ 30 日保持率（≥65%）
│   └─ 前后测词汇量增长（≥30%）
└─ 增长与成本
    ├─ 自然搜索 UV 占比（≥30%）
    ├─ 单篇综合成本（逐批下降）
    └─ 7 日 / 30 日留存（≥25% / ≥15%）
```

### 8.2 验收基线

| 类别 | 指标 | 基线 | 统计口径 |
|---|---|---|---|
| 内容 | 覆盖率 | 100% | 构建门禁 |
| 内容 | 复现达标率 | ≥95% | 看板 |
| 内容 | 缺陷率 | <1 处/千词 | 每月抽样 5% |

### 8.3 埋点清单（最小集）

## 10. 附录

### 附录 A：词表与篇目字段规范

**Lexicon（必填）**：`lemma`、`pos[]`、`stars`、`senses[]`（至少 1 个，含 `zh` 与 `pattern`）、`sets[]`、`status`。
**Lexicon（选填）**：`freq`、`exams[]`、`cefr`、`collocations[]`、`forms[]`、`assign`、`notes`。

**Passage（必填）**：`id`（`{set}-l{level}-u{unit}-{order}`）、`set`、`level`、`unit`、`order`、`title`、`topic`、`genre`、`grammar`、`targets[]`、`recycle[]`、`metrics`、`status`、`version`。
**Passage（选填）**：`glosses[]`、`audio`、`translations`、`questions[]`、`changelog`。

### 附录 B：分配账簿格式

```tsv
lemma	set	level	unit	first_passage	recycle_passages	occ	status
abandon	s3000	3	4	s3000-l3-u04-02	s3000-l3-u05-01|s3000-l4-u01-03	3	published
```

规则：`occ = 1 + recycle_passages.length`；`status ∈ {unassigned, assigned, drafted, reviewed, published}`；`published` 前 `occ` 必须达到星级要求。

### 附录 C：术语

| 术语 | 含义 |
|---|---|
| lemma | 词元，词典收录的基本形式（如 go，而非 went） |
| type / token 覆盖 | 词表里覆盖了多少个不同的词 / 文本中覆盖了多少比例的词次 |
| 生词密度 | 本篇首次出现的词数 ÷ 篇长 |
| 复现达标 | 某词在正文中的目标词出现次数达到星级要求 |
| 受控词汇写作 | 只用规定词集写作，控制难度 |
| SRS | 间隔重复系统（Spaced Repetition System） |
