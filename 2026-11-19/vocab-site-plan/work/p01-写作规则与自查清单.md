# p01 写作规则与自查清单（2026-11-21 新参数版）

**事实源**：`data/assignment.tsv`（分篇词表）、`data/lexicon.json`（词性/释义/星级/词形）。
**产物**：`data/content/pNN.json`，字段与 `site/src/lib/catalog.server.ts` 的 `PassageContent` 一致。
**校验**：`python3 work/qc_check.py data/content/pNN.json`（只读 `data/`，不写文件）。

> 本版参数取代旧版「每词 2 次 + 55–63% 密度 + 闭集写作」。旧配对回环稿已删除。

---

## 1. 参数与 p01 实测

| 指标 | 新参数 | p01 实测 |
|---|---|---|
| 篇长 | 280–320 词 | **302** |
| 句数 | 由句长与篇长推出（20–40） | **28** |
| 句长 | 每句 8–14 词 | 10–13，平均 10.79 |
| 每句生词 | 2–4 个目标词 | 2–4，无越界 |
| 目标词覆盖 | 60 个各 ≥1 次 | **60/60**，无缺词 |
| 目标词次 T | 18%–22% × L | 66 / 302 = **21.9%** |
| 复现 | 允许，不强制 | 6 词各 2 次（the/and/small/car/lady/phone） |
| 可用词性 | 名 ≥30 / 动 ≥20 / 形副 ≥10 | 42 / 31 / 20 |
| 句式模板 | 3 个，各 ≥3 次 | My+N+V(3)、A+形+N+V(4)、During/Then/Later 开头(3) |
| 非目标词 | 常用日常词，不设闭集 | 约 78%（236 词次） |

**口径**：这里的「生词」= 目标词词次。60 个词对读者都是新词，所以句内出现 2–4 个目标词即为合格，不区分首现/复现。

## 2. 动手前的预算

```text
k  = 本篇目标词数（主线 59/60，补漏 57/58）
L  = 篇长，280–320
n  = 句数，n ≈ L / 11（每句 8–14 词）
T  = 目标词次，0.18L ≤ T ≤ 0.22L，且 T ≥ k
重复预算 R = floor(0.22L) − k
```

60 词、L=302 时：`T` 的允许区间是 54.4–66.4，重复预算 `R = 66 − 60 = 6`。
句数下限 `ceil(k/4)=15`，上限 `k/2=30`；p01 取 28 句，是因为 302 词 ÷ 11 ≈ 27.5。

**三条硬边界**：

1. `the / and / or / then / over / during` 本身是目标词，每个都占词次预算，尤其 `the`、`and` 出现一次就 +1。
2. 加长叙事会**降低**密度，删句子会**抬高**密度；密度越界时优先改非目标词的多少，而不是删目标词。
3. 60 个词各一次时 T=60；302 词下密度 19.9%。要贴近 22%，只能靠 4–6 个复现词，不能靠堆句子。

## 3. 写作方法（p01 实际流程）

### 3.1 先分叙事弧，再分句

按词义把 60 词分进 3 个场景段，避免「按字母/词表顺序硬塞」：

| 段 | 场景 | 目标词次（22 + 28 + 16 = 66） |
|---|---|---|
| 1（S1–S9，9 句） | 早餐 + 俱乐部训练 + 街上的车来电 | son, baseball, breakfast, during, course, fourteen, practice, daughter, small, club, university, group, hour, almost, step, then, lady, phone, car, expensive, and, street |
| 2（S10–S21，12 句） | 猜车主、河边傍晚、宠物与狗 | suppose, lock, rich, taste, or, afford, unit, hope, spend, continue, the, develop, river, over, rest, sail, peace, swing, moon, pet, jump, tired, head, neck, weight（外加 and / car / small 三个复现） |
| 3（S22–S28，7 句） | 集市、苦饮料与谎言、分箱防事故、收束 | wrong, fair, bitter, promise, lie, guest, favourite, separate, prevent, accident, enemy, memory, appointment（外加 the / lady / phone 三个复现） |

分配原则：

- 具体名词、动作动词放前两段（有画面）；抽象词（enemy / memory / peace）放收尾的短反思句。
- 每句 2–4 个目标词，先排「词 → 句」的分配表，再写英文，不边写边找词。
- 60 词的分配结果：19 句×2 词 + 8 句×3 词 + 1 句×4 词 = 66 词次。

### 3.2 写句

- 每句 10–13 词，主谓宾完整，用一般现在时/过去时，一句一个画面或一个动作。
- 句内目标词必须**语义成立**：`unit` 指汽车部件，`swing` 指船摇晃，`weight` 指脖子上的分量，`enemy` 指恐惧。
- 非目标词用常用日常词（`slow / little / old / wave / boxes / repairs`），不用专名、不用习语、不用从句套从句。
- 复现只给「锚点词」：`the / and` 便于衔接，`car / lady / phone` 让第 8、12、28 句前后呼应。其余词只出现一次。

### 3.3 保证 60 词全覆盖

用「分配表」而不是事后数：

```text
1  句 → 词 A B C        2  句 → 词 D E        …        28 句 → 词 …
每行 2–4 个，写完 28 行正好 60 个不重复的词
```

写完后跑脚本，`targets <1` 必须为空；若有漏词，优先把该词塞进相邻句的非目标词位置，
而不是新增一句（新增句会同时改变词数、密度、句均长）。

### 3.4 外围素材

- **译文**：逐句直译，保留原文语序信息；`paragraphs` 与 `en` 句数必须相等。
- **词卡**：60 张，顺序与 `assignment.tsv` 一致；`collocation` 必须是正文里的**原样片段**（脚本会校验）。
- **b2 整句挖空**：10 条，挖 1 个词，`hint` 给 2 个字母，`before + answer + after` 必须能回拼原句。
- **b3 首字母**：10 条，`hint` 给 1 个字母，同样要求回拼。
- **b4 回译**：5–6 条中文 + `keywords`（2–3 个目标词）。
- **8 题**：词义 2–3 题、语境填空 3–4 题、搭配 1 题；`answer` 为选项索引且分散。

## 4. 约束怎么互相牵制

| 冲突 | 机理 | 处理 |
|---|---|---|
| 目标词密度 18–22% vs `the/and` | 这两个也是目标词，自然行文里最容易超支 | 全文 `the` 只用 2 次、`and` 2 次；其余用 `my/our/that/but/so` 和分号 |
| 每句 2–4 词 vs 每词一次 | 60 词按 2 词/句需要 30 句，但 302 词只够 28 句 | 允许 8 句放 3 个词、1 句放 4 个词（p01 的做法） |
| 篇长 280–320 vs 密度 | 加非目标词会稀释密度，删句子会浓缩密度 | 密度 >22% 就加环境描写；<18% 就删修饰语，不动目标词 |
| 单次覆盖 vs 记忆效果 | 新参数不强制两次，复现靠后续篇目和 SRS | 复现预算只给 6 个锚点词，不硬塞同义改写 |
| 叙事连贯 vs 词表随机 | 60 词跨棒球/汽车/河流/集市四个域 | 用「一个周六」的单线时间轴串起来，抽象词放结尾反思 |
| 搭配字段 vs 正文 | 词卡搭配必须逐字出现在正文 | 写完正文再回填搭配，不从词典抄例句 |
| 旧 R2 闭集规则 | 18–22% 密度下不可能只靠目标词 + 功能词成文 | 非目标词放开为常用日常词，但禁止专名、低频词、习语 |

## 5. 后续篇目怎么复制

1. 取 `assignment.tsv` 的 `pNN` 词表，k = 59/60（补漏 57/58）。
2. 定 L：`L = 300`（280–320 内均可）；算 `T` 区间与复现预算 `R`。
3. 分 3–4 个场景弧，做「词 → 句」分配表，每句 2–4 词，句数 ≈ L/11。
4. 写英文（8–14 词/句），先保证叙事成立，再微调词数。
5. 跑 `qc_check.py`，按 `RESULT` 逐项修；`FAIL` 里最常见的是密度越界和搭配不是原样片段。
6. 写译文、词卡、b2/b3/b4、8 题、`metrics`，再跑一次脚本确认全绿。
7. 只改 `data/content/pNN.json` 与 `work/`，不动 `site/`、`outputs/`。

## 6. 内容文件字段（对齐加载器）

```jsonc
{
  "id": "p01",
  "title": "A Saturday by the River", "titleZh": "河边的星期六", "topic": "日常",
  "paragraphs": [[{ "en": "...", "zh": "..." }, ...], ...],   // 必须是「数组的数组」，9/12/7 段
  "words": [{ "lemma": "the", "pos": "art.", "zh": "这；那（定冠词）",
              "stars": 5, "collocation": "the children" }],  // stars 加载器会忽略，保留待用
  "quiz": [{ "id": "q1", "type": "词义匹配", "prompt": "...",
             "options": ["A","B"], "answer": 1, "speak": "group" }],  // answer 是索引
  "recite": {
    "b2": [{ "before": "...", "hint": "br", "after": "...", "answer": "breakfast" }],
    "b3": [{ "before": "...", "hint": "d",  "after": "...", "answer": "daughter" }],
    "b4": [{ "zh": "...", "keywords": ["son", "baseball"] }]
  },
  "metrics": { "words": 302, "sentences": 28, "newDensity": 0.199,
               "targetTokenDensity": 0.219, "patterns": ["..."] }
}
```

- `b2/b3` 的 `answer` 必须是单个词，前端按整串小写比较，多词必错。
- `metrics.newDensity` = 唯一目标词数 / 总词数；`targetTokenDensity` = 目标词次 / 总词数。
- `paragraphs` 用嵌套数组；扁平数组会被加载器按每 3 句一段重切。

## 8. p01 的取舍记录

1. **不再每词两次**：60 词各一次，6 个锚点词复现一次；密度因此落在 21.9%。
2. **非目标词放开**：旧闭集规则与新密度参数不兼容，非目标词限定为常用日常词（脚本只统计、不设上限）。
3. **叙事优先**：词按场景弧分配，个别词义做了场景化处理（`unit` = 汽车部件，`enemy` = 恐惧）。
4. **20 句以上**：28 句是 302 词 ÷ 10.8 的结果；若后续篇目想压到 22 句，每句需 13–14 词，接近上限。
